1. Функциональные зависимости
source_wh - source_city
dest_wh - dest_city
product_id - category_name
transfer_id - source_wh, dest_wh, created_at
transfer_id, product_id - qty

2. Потенциальный ключ через замыкание
Ключ исходной таблицы — (transfer_id, product_id).
* По transfer_id получаем оба склада и дату перемещения, а по кодам складов — их города.
* По product_id получаем категорию товара.
* По паре (transfer_id, product_id) получаем количество qty.

Замыкание пары содержит все атрибуты transfer_flat. Ключ минимален: одного transfer_id недостаточно, чтобы определить товар, а одного product_id — чтобы определить перемещение.

3. Частичные и транзитивные зависимости
Частичная: transfer_id - source_wh, dest_wh, created_at и product_id - category_name. Для каждой зависимости достаточно части ключа.

Транзитивная	transfer_id - source_wh - source_city и transfer_id - dest_wh - dest_city. Город определяется через код склада.

4. Аномалии исходной таблицы
INSERT: Нельзя добавить склад сам по себе. Для строки нужны ещё перемещение и товар.
UPDATE: Если город склада записан в нескольких строках, его исправление придётся внести в каждую из них.
DELETE: При удалении последней строки с товаром теряется и информация о его категории.

5. Декомпозиция до 3НФ
Переход к 2НФ. По зависимости transfer_id - source_wh, dest_wh, created_at выносим общие данные перемещения в transfers, пока вместе с городами. По зависимости product_id - category_name выносим категорию в products. В transfer_items оставляем transfer_id, product_id и qty.

Переход к 3НФ. По зависимости warehouse - city выносим города в warehouses. В transfers остаются коды складов. Оба кода ссылаются на один справочник.

6. Проверка НФБК
Четыре итоговые таблицы находятся в НФБК: в каждой таблице левая часть каждой нетривиальной зависимости является ключом или содержит ключ. Все исходные зависимости сохраняются. Исходную плоскую таблицу можно восстановить соединениями по ключам, причём warehouses присоединяется дважды — для отправителя и получателя.
